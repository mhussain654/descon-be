# Training videos rollout

Training videos replace the old external training link. Staff with `manage_training_settings` request a short-lived direct upload ticket from Rails, PUT the MP4 to private S3, then create an unpublished TrainingVideo with the returned signed blob ID. Candidates only see published videos. Rails never proxies the full upload or playback body through the 2 GiB EC2 instance. The upper limit is **250 MiB per MP4**; the client sample is 170 MB.

Before uploading in production, the AWS administrator must apply `deploy/aws/training-video-cors.json` to `descon-mps-documents-s3-bucket` using S3 → Permissions → CORS (or `aws s3api put-bucket-cors --bucket descon-mps-documents-s3-bucket --cors-configuration file://deploy/aws/training-video-cors.json`). This is browser CORS for direct PUT from `https://descon-mps.com`. Preserve any existing bucket CORS rules needed elsewhere when applying it. Keep S3 Block Public Access enabled. The EC2 role needs existing S3 Put/Get/Delete permissions; no AWS keys are put in the browser. The upload URL is a temporary signed S3 URL. Rails verifies the staff owner, age, content type, size and MP4 signature before attaching. It does not perform malware scanning or transcoding.

Deploy backend first and migrate all production databases via the existing Capistrano process. The old `training_settings` table and endpoints are removed; its prior link value is discarded. Deploy the frontend after the backend is healthy, then build and distribute the mobile application. Roll out together to avoid old mobile builds attempting the removed training-link endpoint. On the admin Training page, upload a short MP4, preview it, publish, then verify it appears and plays on Android and iOS in both English and Urdu. Confirm unpublish removes it from candidate lists. Do a separate 170 MB upload on production to validate S3 CORS and network behavior; local test storage is not representative.

S3 retains incomplete direct uploads as unattached blobs if the browser closes mid-flow. Review cleanup for old training-tagged unattached ActiveStorage blobs as a separate maintenance task before automating purge, so unrelated uploads are unaffected.
